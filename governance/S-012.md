# S-012 — Dependency Discipline

Constitution text: *"Every dependency must be declared, approved, and justified.
A dependency (library, service, tool, data source) introduced without an
approved requirement and recorded justification is a violation. Transitive
dependencies are subject to the same standard; undeclared transitive
dependencies are defects."*

---

## STEP 2 — Problem

Every dependency is an uninvited guest: supply-chain risk, licensing risk,
drift risk. When a library sneaks in transitively — or a direct dependency
arrives without anyone saying why — the system's surface grows without
governance. This rule demands that the FULL resolved dependency graph (direct
AND transitive) is declared, approved, and justified against a requirement.

## STEP 3 — Concepts

- dependency
- declared
- approved
- justified
- transitive dependency
- defect

## STEP 4 — Deterministic Definitions

| Concept | Definition |
|---------|-----------|
| dependency | GLOSSARY §13: library, service, tool, or data source referenced by the implementation. |
| declared | A record exists with `name`, `version` (pinned, per S-008), `requirementId`, `justification` (non-empty, references the requirement), and an approving governed decision (`decision` = `EXECUTE`). |
| approved | The declaring record's governed decision is valid (GLOSSARY §1). |
| justified | `justification` text is non-empty and names the requirement id it satisfies. |
| transitive dependency | Any dependency in the resolved graph that is not a direct declaration. |
| defect | A name in the resolved graph with no declaring record (undeclared transitive), or a declaration missing any declared-field. |

## STEP 5 — Required State

- `dependencies[]` (declared records)
- `resolvedDependencyGraph[]` (fully resolved names including transitive)
- `requirements[]` (the justified requirement must be approved)
- `decisions[]`

## STEP 6 — Triggers

- At dependency introduction
- On manifest change
- After resolution (graph re-check)

## STEP 7 — Algorithm

```
FOR each name ∈ resolvedDependencyGraph:
  record = dependencies.find(d => d.name = name)
  IF record = undefined
    THEN fail: "Undeclared dependency '{name}' (incl. transitive) — defect."

  IF NOT isDeclared(record)          // GLOSSARY §13 all fields present
    THEN fail: "Dependency '{name}' is missing declaration fields."

  IF NOT isApproved(record.approval) // GLOSSARY §1
    THEN fail: "Dependency '{name}' is not approved."

  IF record.justification = '' OR NOT justificationReferences(record, record.requirementId)
    THEN fail: "Dependency '{name}' is not justified."

  req = requirements.find(id = record.requirementId)
  IF req = undefined OR NOT isApprovedRequirement(req)
    THEN fail: "Dependency '{name}' justifies against an unapproved requirement."

pass
```

## STEP 8 — Tests

| Class | Case | Expected |
|-------|------|----------|
| normal | Direct dependency declared, approved, justified, requirement approved | pass |
| normal | Transitive dependency with its own declaration record | pass |
| failure | Undeclared transitive dependency in resolved graph | fail |
| failure | Declared but approval decision = `RETRIEVE_EVIDENCE` | fail |
| failure | Empty justification | fail |
| failure | Justification names a draft requirement | fail |
| edge | Dependency declared but never actually used | warning-level consideration, not governed by this rule (leave declared) |
| edge | Tool dependency (build tool) with requirement traced | pass |
| regression | S-008 pin requirement enforced alongside | compose cleanly |
| adversarial | Two records with the same name, different versions (alias attack) | fail (name uniqueness in resolved graph) |
| adversarial | Approval decision timestamped after resolution | fail (approval must predate the record's use) |

## STEP 9 — Conflicts

- S-008: pinned versions — this rule's `version` field must be pinned. Consistent.
- S-001/S-007: the justification's requirement must be approved — same standard.
