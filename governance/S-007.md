# S-007 — Traceable Engineering

Constitution text: *"Every engineering artifact shall trace to an approved
requirement. ... Traceability is not optional documentation; it is a
first-class governed relationship."*

---

## STEP 2 — Problem

Artifacts float free of intent: nobody can say which requirement a test, a
config, a doc, or a deployment serves. This rule makes the trace a structural
property of every artifact, not prose: an artifact without a trace to an
approved requirement does not exist as a governed artifact.

## STEP 3 — Concepts

- artifact
- trace
- requirement identifier
- first-class relationship

## STEP 4 — Deterministic Definitions

| Concept | Definition |
|---------|-----------|
| artifact | GLOSSARY §9: kind ∈ {source, test, configuration, documentation, deployment}. |
| trace | GLOSSARY §10: recorded in artifact metadata as `trace` = requirement id. |
| valid trace | `trace` maps to an Approved Requirement (GLOSSARY §3) at evaluation time. |
| first-class | The trace is part of the artifact record (machine-readable), not prose in the artifact body. |

## STEP 5 — Required State

- `artifacts[]` (kind + trace)
- `requirements[]` (approval status)
- `decisions[]` (approval records)

## STEP 6 — Triggers

- At acceptance of EVERY artifact of the five kinds
- On requirement amendment (traces re-validated)

## STEP 7 — Algorithm

```
FOR each artifact ∈ artifacts:
  IF artifact.kind ∉ {source, test, configuration, documentation, deployment}
    THEN continue (not an engineering artifact)

  IF artifact.trace = undefined OR artifact.trace = ''
    THEN fail: "Artifact '{artifact.id}' has no requirement trace."

  req = requirements.find(id = artifact.trace)
  IF req = undefined
    THEN fail: "Artifact '{artifact.id}' traces to a nonexistent requirement."
  IF NOT isApprovedRequirement(req)
    THEN fail: "Artifact '{artifact.id}' traces to unapproved requirement '{req.id}'."

pass
```

## STEP 8 — Tests

| Class | Case | Expected |
|-------|------|----------|
| normal | Source file traced to approved requirement | pass |
| normal | Test/config/documentation/deployment artifacts each traced | pass |
| failure | Artifact without trace | fail |
| failure | Trace to nonexistent requirement id | fail |
| failure | Trace to draft/rejected requirement | fail |
| edge | Trace written in artifact body prose only (not metadata) | fail (not first-class) |
| edge | Non-engineering artifact (e.g., image asset outside kinds) | skipped |
| regression | Requirement approved after artifact created | fail unless trace re-validated at acceptance time (approval must predate acceptance) |
| adversarial | Artifact with trace to a requirement whose approval was later revoked | fail |
| adversarial | Duplicate artifact ids with different traces | fail (id uniqueness) |

## STEP 9 — Conflicts

- S-010: trace granularity must not force unrelated work (an artifact traces to
  the requirement it serves — minimal). No conflict.
- S-003: traced conformance is how contradictions are detected. No conflict.
