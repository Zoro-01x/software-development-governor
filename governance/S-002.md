# S-002 — Code Is Evidence

Constitution text: *"Generated or written code is not proof of correctness.
Only passing automated verification constitutes evidence that an implementation
satisfies its requirements."*

---

## STEP 2 — Problem

"Look, the code exists" is the most common false proof in software. Code that
compiles, renders, or runs once demonstrates nothing about whether it satisfies
its requirements. This rule refuses to count code as evidence: only passing
automated verification is evidence.

## STEP 3 — Concepts

- code
- evidence
- correctness
- automated verification
- claim

## STEP 4 — Deterministic Definitions

| Concept | Definition |
|---------|-----------|
| code | Any artifact of kind `source`. |
| evidence | GLOSSARY §6: deterministic, reproducible, not dependent on uncontrolled external state. |
| passing automated verification | GLOSSARY §7: `pass=true`, `reproducible=true`, `externalStateDependency=false`, `sourceVersion` matches the artifact. |
| claim supported | A claim is supported iff a passing automated verification run is linked to its target artifact. |
| code-only claim | A claim whose only backing record is the artifact itself. Code-only claims are NOT supported. |

## STEP 5 — Required State

- `claims[]` (each with `targetArtifactId`)
- `verificationRuns[]` (with `targetArtifactId`, `pass`, `reproducible`, `externalStateDependency`, `sourceVersion`)
- `artifacts[]` (sourceVersion of the code)

## STEP 6 — Triggers

- At verification stage, for every claim about implementation behavior
- On any claim registration

## STEP 7 — Algorithm

```
FOR each claim ∈ claims:
  runs = verificationRuns.filter(r =>
    r.targetArtifactId = claim.targetArtifactId
    AND isPassingAutomatedVerification(r)      // GLOSSARY §7
    AND r.sourceVersion = artifact(claim.targetArtifactId).sourceVersion)
  IF runs = ∅
    THEN fail: "Claim '{claim.id}' has code but no passing automated verification."

pass
```

## STEP 8 — Tests

| Class | Case | Expected |
|-------|------|----------|
| normal | Claim backed by a passing, reproducible run | pass |
| edge | Multiple claims, one unsupported | fail, unsupported claim identified |
| failure | Claim backed only by code artifact | fail |
| failure | Verification run exists but `pass=false` | fail |
| failure | Run passes but `reproducible=false` | fail (not evidence) |
| failure | Run passes but `externalStateDependency=true` | fail |
| failure | Run passes but was executed against an older `sourceVersion` | fail (stale run is not evidence) |
| regression | Claim that passed yesterday still passes today (same source) | pass |
| adversarial | Verification run forged with no `sourceVersion` field | fail (GLOSSARY §7 requires it) |
| adversarial | Run linked to a different artifact id than the claim's | fail |

## STEP 9 — Conflicts

- S-004 is the positive form of this rule (every claim must be demonstrated by
  automated verification). Same check, two views — no conflict.
- S-009 strengthens the definition of valid verification (reproducibility);
  this rule consumes that definition. No conflict.
