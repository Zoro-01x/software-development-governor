# E-001 — Experience Prerequisite

Constitution text: *"No engineering work shall begin without an approved
Experience Architecture."*

---

## STEP 2 — Problem

Engineering can start before anyone validates that the intended human
experience is sound. Result: effort spent building requirements, designs, and
code for an experience that should have been rejected or revised at the
experience stage. This rule makes experience approval a hard prerequisite for
ALL downstream engineering work — requirement analysis, technical design, and
implementation.

The Engineering Governor does not validate experience QUALITY. It verifies only
that experience approval EXISTS. This is the single coupling between the
Experience Governor and the Engineering Governor.

## STEP 3 — Concepts

- engineering work
- approved Experience Architecture
- experience approval
- prerequisite

## STEP 4 — Deterministic Definitions

| Concept | Definition |
|---------|-----------|
| engineering work | A request whose `type` ∈ { `requirement-analysis`, `technical-design`, `implementation` }. |
| experience approval exists | A Governed Decision (GLOSSARY §1) exists in the decision log with `decision` = `EXECUTE`, `target` = `experience-architecture`, and non-empty `validationReportId`. |
| approved Experience Architecture | The subject of an experience approval (above). |
| prerequisite | `NOT experienceApprovalExists ⇒ DENY`, evaluated BEFORE any other engineering rule. |

## STEP 5 — Required State

- `request.type`
- `decisions[]` (search for experience-architecture approval)

## STEP 6 — Triggers

- BEGINNING of every request of engineering-work type
- Not applicable to verification, build, or deployment requests (those carry their own gates)

## STEP 7 — Algorithm

```
IF request.type ∉ {requirement-analysis, technical-design, implementation}
  THEN continue (rule not applicable)
ELSE IF ∃ decision ∈ decisions:
        decision.decision = EXECUTE
        AND decision.target = 'experience-architecture'
        AND decision.validationReportId ≠ ''
  THEN pass
ELSE
  fail with reason: "Experience Architecture not approved."
```

## STEP 8 — Tests

| Class | Case | Expected |
|-------|------|----------|
| normal | Engineering request with valid experience approval | pass |
| edge | Request type = `verification` with no approval | rule not applicable (pass, other rules govern) |
| failure | Engineering request, no approval record | fail, reason exact |
| failure | Approval exists but `decision` = `REVISE` | fail |
| failure | Approval exists but `validationReportId` empty | fail (not a governed decision) |
| regression | Approved experience + valid requirements still passes S-001 | pass (rules compose, no interference) |
| adversarial | Forged approval record missing `reason` | fail (GLOSSARY §1 invalid) |
| adversarial | Approval targeted at `engineering-architecture` instead of `experience-architecture` | fail |

## STEP 9 — Conflicts

- S-001 also gates engineering; E-001 is a prerequisite on the whole engineering
  stream, S-001 on the implementation stage specifically. Complementary.
- No rule permits engineering without experience approval. No conflict.
