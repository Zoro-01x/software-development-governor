# S-010 — Incremental Change

Constitution text: *"All changes shall be minimal with respect to the
requirement they satisfy. A change shall implement exactly the requirement and
no more. Unrelated modifications, speculative refactoring, and undiscovered
feature work are prohibited within a governed change scope."*

---

## STEP 2 — Problem

A "small fix" that also renames three modules and adds an unused utility makes
reviews impossible and hides defects. This rule bounds every change to exactly
the artifacts and hunks its requirements justify — anything else is a
violation, regardless of quality.

## STEP 3 — Concepts

- change scope
- minimal change
- unrelated modification
- speculative refactoring
- undiscovered feature work

## STEP 4 — Deterministic Definitions

| Concept | Definition |
|---------|-----------|
| change | A set of hunks across artifacts, submitted together, with declared `requirementIds[]`. |
| change scope | The artifact set each declared requirement justifies (trace per S-007). An artifact is in scope iff it traces to ≥1 declared requirement. |
| minimal | Every hunk in the change either (a) modifies an in-scope artifact AND (b) is required to satisfy the declared requirements. |
| unrelated modification | A hunk in an in-scope artifact that does not contribute to the declared requirements (rename, reformat of unrelated regions, dead code). |
| speculative refactoring | A hunk with no corresponding requirement text (no trace). |
| undiscovered feature work | A change to an artifact whose trace maps to a requirement NOT declared on the change. |

## STEP 5 — Required State

- `changes[]` (artifactId, hunk list, requirementIds)
- `artifacts[]` (trace)
- `requirements[]`

## STEP 6 — Triggers

- At change submission (before merge/acceptance)

## STEP 7 — Algorithm

```
FOR each change ∈ changes:
  IF change.requirementIds = ∅
    THEN fail: "Change '{change.id}' declares no requirements."

  FOR each hunk ∈ change.hunks:
    artifact = artifacts.find(id = hunk.artifactId)

    // Speculative refactoring / undiscovered feature work
    IF artifact.trace ∉ change.requirementIds
      THEN fail: "Hunk touches artifact '{artifact.id}' outside the declared scope."

    // Unrelated modification
    IF NOT hunkRequiredBy(hunk, change.requirementIds)   // deterministic diff-vs-requirement analysis
      THEN fail: "Hunk in '{artifact.id}' is unrelated to the declared requirements."

pass
```

## STEP 8 — Tests

| Class | Case | Expected |
|-------|------|----------|
| normal | Change with hunks only in traced artifacts, all requirement-driven | pass |
| failure | Change touches an artifact traced to an undeclared requirement | fail |
| failure | Change declares no requirements | fail |
| failure | Hunk in in-scope artifact but unrelated (rename) | fail |
| failure | Speculative refactor with no requirement text | fail |
| edge | Empty change (no hunks) | pass (vacuous) |
| edge | Multi-requirement change, each artifact traced to one declared requirement | pass |
| regression | S-007 trace rules unchanged by scope filtering | compose cleanly |
| adversarial | Hunk hidden in a binary blob or generated file to evade diff analysis | fail (generated artifacts must carry their source-of-generation trace) |
| adversarial | Requirement text stretched after the fact to justify unrelated hunk | fail (requirement amendment = S-006 human approval + forward-only S-003) |

## STEP 9 — Conflicts

- S-001: this rule's scope is the traced requirement set — consistent.
- S-007: trace granularity is the mechanism scope checks use — consistent.
