# S-009 — Reproducible Verification

Constitution text: *"A passing verification must be independently reproducible.
Test results shall be repeatable in an isolated environment from the same
source, requirements, and configuration. Verification that depends on external
state not under the system's control is not considered valid evidence."*

---

## STEP 2 — Problem

A test suite that passes only on the developer's machine, or only while the
staging database is alive, is not verification — it's a coincidence. This rule
strips the "evidence" label from any verification that cannot be repeated in an
isolated environment from controlled inputs.

## STEP 3 — Concepts

- reproducible
- isolated environment
- external state
- valid evidence

## STEP 4 — Deterministic Definitions

| Concept | Definition |
|---------|-----------|
| verification input | The tuple (source, requirements, configuration) at run time. |
| reproducible | The run's outcome (pass/fail) is identical when repeated in an isolated environment from the same verification input. |
| isolated environment | An environment whose runtime dependencies are declared and provisioned by the verification itself; no ambient services, no shared databases, no live external network unless declared as fixtures. |
| external state | State not under the system's control (GLOSSARY §16): live network services, shared databases, wall-clock-dependent logic. |
| valid evidence | A verification run with `reproducible=true`, `externalStateDependency=false`, and a declared environment fingerprint (GLOSSARY §7). |

## STEP 5 — Required State

- `verificationRuns[]` (`reproducible`, `externalStateDependency`, environment fingerprint, `sourceVersion`)
- `artifacts[]` (sourceVersion matching)

## STEP 6 — Triggers

- At verification result acceptance (before the run counts as evidence)
- On re-verification of amended requirements

## STEP 7 — Algorithm

```
FOR each run ∈ verificationRuns:
  IF run is not offered as evidence (no claim linked): continue

  IF run.reproducible ≠ true
    THEN fail: "Verification run '{run.id}' is not reproducible — not valid evidence."

  IF run.externalStateDependency ≠ false
    THEN fail: "Verification run '{run.id}' depends on external state — not valid evidence."

  IF run.environmentFingerprint = undefined OR run.environmentFingerprint = ''
    THEN fail: "Verification run '{run.id}' lacks an environment fingerprint."

  IF run.sourceVersion ≠ artifact(run.targetArtifactId).sourceVersion
    THEN fail: "Verification run '{run.id}' does not match artifact source version."

pass
```

## STEP 8 — Tests

| Class | Case | Expected |
|-------|------|----------|
| normal | Passing run, reproducible, isolated, fingerprinted, version-matched | pass |
| failure | `reproducible=false` | fail |
| failure | `externalStateDependency=true` (live DB, network service) | fail |
| failure | No environment fingerprint | fail |
| failure | Source version mismatch | fail |
| edge | Run linked to no claim | skipped (not evidence for anything) |
| edge | Run passing twice in dev, failing once in CI | fail (not reproducible) |
| regression | S-002 consumes this rule's definition of valid evidence | compose cleanly |
| adversarial | Fingerprint string copied from another environment | fail if fingerprint content does not match the run's declared environment record |
| adversarial | External dependency removed after the fact from the record | fail (declaration must be captured at run time — immutable record) |

## STEP 9 — Conflicts

- S-008: build determinism vs verification reproducibility — disjoint
  (artifacts vs outcomes). No conflict.
- S-002/S-004: they define evidence and claims; this rule defines what makes
  verification valid. Consumed, not conflicting.
