# S-011 — Architectural Integrity

Constitution text: *"Implementation must conform to its governing architecture.
No component shall violate the dependency direction, interface contract, or
structural constraint defined by the approved architecture for that scope.
Architectural drift is a governed violation even if all tests pass."*

---

## STEP 2 — Problem

Tests go green while the system quietly drifts out of its architecture: a
component imports across a forbidden boundary, calls a contract it doesn't own,
or bypasses a structural rule. Drift is invisible to tests. This rule makes
conformance to the approved architecture a first-class governed check that
tests cannot override.

## STEP 3 — Concepts

- architecture
- constraint
- dependency direction
- interface contract
- structural constraint
- drift

## STEP 4 — Deterministic Definitions

| Concept | Definition |
|---------|-----------|
| approved architecture | The architecture record with `approved=true` and a valid approval decision. |
| constraint | A machine-readable rule from the approved architecture of one of three kinds: dependency-direction (component X may depend only on set D(X)), interface-contract (component X implements interface I(X) with declared members), structural (component X must/should not contain pattern P). |
| drift | An implementation element (component, module, file) that violates ≥1 constraint of the approved architecture for its scope (GLOSSARY §14). |
| violation | `drift` detected by automated static analysis of the artifacts against the constraint set. Test results are NOT input to this evaluation. |

## STEP 5 — Required State

- `architecture` (`approved`, `constraints[]`)
- `architecture.violations[]` (automated analysis findings: constraint id, artifact id)
- `artifacts[]`
- `decisions[]` (approval)

## STEP 6 — Triggers

- At implementation acceptance
- At architecture change (constraints updated)

## STEP 7 — Algorithm

```
IF architecture = undefined
  THEN continue (no governing architecture in context)

IF NOT isApprovedArchitecture(architecture)
  THEN fail: "Architecture is not approved — cannot be a governing specification."

// Tests are irrelevant to this rule by definition:
FOR each violation ∈ architecture.violations:
  IF violation is unresolved (no approved exception)
    THEN fail: "Drift: artifact '{artifact}' violates constraint '{constraint}'."

// Declared constraints must be analyzable:
FOR each constraint ∈ architecture.constraints:
  IF constraint lacks a target scope (component or component set)
    THEN fail: "Constraint '{constraint.id}' has no analyzable scope."

pass
```

## STEP 8 — Tests

| Class | Case | Expected |
|-------|------|----------|
| normal | Implementation conforms, architecture approved | pass |
| failure | Drift recorded (dependency direction violated) | fail |
| failure | Interface contract violated | fail |
| failure | Structural constraint violated | fail |
| edge | All tests pass AND drift exists | fail (drift wins over green tests) |
| edge | Architecture not approved | fail (no valid governing spec) |
| failure | Constraint with no scope | fail (unanalyzable) |
| regression | S-003 verdicts align with S-011 (spec authority) | compose cleanly |
| adversarial | Drift hidden in generated code | fail (generated code is implementation; its source-of-generation must conform too) |
| adversarial | Approved exception for the drift recorded after acceptance | fail (exception must predate acceptance — forward-only) |

## STEP 9 — Conflicts

- S-003: same verdict semantics, disjoint inputs (requirement text vs
  architecture constraints). No conflict.
- S-006: architecture constraint changes are architectural decisions → human
  approval required. Consistent.
