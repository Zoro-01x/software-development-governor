# S-006 — Human Approval

Constitution text: *"Architectural decisions, requirement changes, and
deployment approvals require explicit human consent. Routine implementation
within an approved scope may proceed without human intervention."*

---

## STEP 2 — Problem

An autonomous system could amend requirements, redesign the architecture, or
ship to production on its own. This rule draws the boundary: decisions that
change the contract with the user (requirements), the structure of the system
(architecture), or what the user receives (production deployments) require
explicit human consent. Everything else inside an approved scope proceeds
automatically.

## STEP 3 — Concepts

- architectural decision
- requirement change
- deployment
- human consent
- routine implementation
- approved scope

## STEP 4 — Deterministic Definitions

| Concept | Definition |
|---------|-----------|
| human consent | Human Approval (GLOSSARY §2): governed decision with a human `authorizedBy` / `issuerId`. |
| architectural decision | A decision altering any constraint of the approved architecture (add, remove, or change a dependency-direction, interface-contract, or structural constraint — see S-011). |
| requirement change | GLOSSARY §4 (alter approved requirement text/status/scope). Initial approval is NOT a change. |
| deployment | A request of type `deployment` whose `environment.role` = `production`. |
| routine implementation | An implementation request inside its approved scope (all traced requirements approved, no amendment). |
| approved scope | The set of Approved Requirements (GLOSSARY §3) traced to the request at evaluation time. |

## STEP 5 — Required State

- `request.type`
- `environment.role` (for deployments)
- `decisions[]` (with `authorizedBy`/`issuerId`)
- `requirements[]` (change detection: amended vs. approved baseline)
- `architecture` (constraint baseline + proposed changes)

## STEP 6 — Triggers

- When a decision of kind ∈ { architecture, requirement-change, deployment } is proposed
- Never for routine implementation inside approved scope

## STEP 7 — Algorithm

```
IF request.type = 'deployment':
  IF environment.role ≠ 'production': continue (not production → not governed here)
  IF NOT humanConsent(request): fail: "Production deployment requires human approval."
  pass

IF request proposes a requirement change:
  IF NOT humanConsent(change): fail: "Requirement change requires human approval."
  pass

IF request proposes an architectural decision:
  IF NOT humanConsent(decision): fail: "Architectural decision requires human approval."
  pass

// routine implementation within approved scope
IF request.type = 'implementation'
  AND all traced requirements approved
  AND no amendment attached:
  pass without human consent.

fail: "Request outside approved scope without human approval."
```

## STEP 8 — Tests

| Class | Case | Expected |
|-------|------|----------|
| normal | Routine implementation, approved scope | pass, no human needed |
| normal | Production deployment with human approval | pass |
| normal | Requirement amendment with human approval | pass |
| failure | Production deployment, no human approval | fail |
| failure | Requirement change (amend) approved by system decision | fail |
| failure | Architectural constraint change without human consent | fail |
| edge | Deployment to `staging` | rule not applicable |
| edge | Initial requirement approval (not a change) | pass without human |
| regression | E-001 still gates engineering before this rule runs | compose cleanly |
| adversarial | Human approval record reused for a different decision (mismatched `decisionId`) | fail |
| adversarial | `authorizedBy` = a known system/agent id | fail (not human) |
| adversarial | Approval timestamp after the change it authorizes | fail |

## STEP 9 — Conflicts

- S-001: initial requirement approval is a governed decision, NOT a requirement
  change — humans not required at first approval (resolution in README).
- S-005: assumptions amending approved requirements are requirement changes →
  human approval required (GLOSSARY §11).
